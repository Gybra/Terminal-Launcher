# Safety model

Locking the screen, opening the notification shade, opening quick settings, and opening Overview are the privileged Android capabilities the launcher can hold. They share one accessibility service declaring the least it can: no window content, no gestures, and no accessibility event, so nothing on screen is ever read. The service is turned on only in Android's accessibility settings, never automatically. First use shows a separate prominent in-app disclosure of the four actions and the absence of screen reading. Agree saves consent locally before opening Android settings; Not now, Back and outside dismissal do not grant consent or open settings. All four action callbacks require saved consent, even if an older installation already had the service enabled. Declining keeps normal app search and launching available, and gestures remain silent even if saving the refusal fails. Only an explicit request through Settings reopens the disclosure. Turning an active setting off turns the service off. A legacy service left enabled after refusal remains inert and can be disabled in Android settings. The only calls it makes are `performGlobalAction` for `GLOBAL_ACTION_LOCK_SCREEN`, `GLOBAL_ACTION_NOTIFICATIONS`, `GLOBAL_ACTION_QUICK_SETTINGS`, and `GLOBAL_ACTION_RECENTS`: the lock the power button performs, the two panels the status bar opens, and the recents switcher. The launcher holds no device-admin privilege, never forces the PIN that `DevicePolicyManager.lockNow()` would, and never uses hidden status-bar APIs.

Consent is stored separately from Android permission. Missing or unknown consent fails closed, and a failed consent write never opens Android settings. A failed attempt to remember Not now does not trap the user behind the notice; it can be offered again on a later launcher start. The privacy policy is available offline from Settings, covers local preferences, launch ranking and optional notification counts, and provides the public support contact. Reading it opens no website and grants no permission.

The project never executes real shell commands. `Runtime.exec`, `ProcessBuilder`, `/bin/sh`, `su`, shell passthrough, arbitrary Intent URIs, and unregistered commands are outside the architecture. Prompt input is tokenized and matched against explicitly registered commands only, and anything else falls back to application search. Every command maps to a controlled Android API or an explicit safe Intent: an Intent is never built from prompt input, and the only package name that ever reaches one is a package discovered through `PackageManager` and resolved to exactly one application. Every future command must meet the same rule.
