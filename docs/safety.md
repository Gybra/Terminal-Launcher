# Safety model

Locking the screen, opening the notification shade, and opening quick settings are the privileged Android capabilities the launcher can hold. They share one accessibility service declaring the least it can: no window content, no gestures, and no accessibility event, so nothing on screen is ever read. The service is turned on only in the Android accessibility settings, is never requested at startup, and turns itself off the moment the setting is turned off. The only calls it makes are `performGlobalAction` for `GLOBAL_ACTION_LOCK_SCREEN`, `GLOBAL_ACTION_NOTIFICATIONS`, and `GLOBAL_ACTION_QUICK_SETTINGS`: the lock the power button performs and the two panels the status bar opens. The launcher holds no device-admin privilege, never forces the PIN that `DevicePolicyManager.lockNow()` would, and never uses hidden status-bar APIs.

The project never executes real shell commands. `Runtime.exec`, `ProcessBuilder`, `/bin/sh`, `su`, shell passthrough, arbitrary Intent URIs, and unregistered commands are outside the architecture. Prompt input is tokenized and matched against explicitly registered commands only, and anything else falls back to application search. Every command maps to a controlled Android API or an explicit safe Intent: an Intent is never built from prompt input, and the only package name that ever reaches one is a package discovered through `PackageManager` and resolved to exactly one application. Every future command must meet the same rule.
